# 2026.250.0635 — mcp: P2 — children inherit the full environment; reconcile project prefix

## Summary

Implements plan principles **P2** (the environment is authoritative; charly never strips CHARLY env vars) and **P3** (loopback-only by default) plus the §3.7 prefix reconciliation in `candy/plugin-mcp`:

1. **`childCharlyEnv()` no longer strips anything.** It previously returned `spec.ChildProjectEnv(os.Environ(), "")`, which removed `CHARLY_PROJECT_DIR` / `CHARLY_PROJECT_REPO` from every forked child. It now returns the FULL environment (`os.Environ()`): a child charly inherits every CHARLY_* variable verbatim — the user's environment IS their intent, and the config resolution precedence (env → flag → --repo → cwd) already makes the env win when set. Both `forkCharly` (tool calls) and `runCLIModel` (the startup `__cli-model` fetch) inherit the same full environment.

2. **`computeProjectPrefix` is reconciled so the fallback prefix never fights the environment.** New order: (1) `CHARLY_PROJECT_DIR` or `CHARLY_PROJECT_REPO` set in the environment → `nil` (the environment is authoritative; the child inherits and resolves it — NEVER pass `--repo` while `--dir` is set, they are mutually exclusive in the charly CLI); (2) else charly.yml in cwd → `nil`; (3) else `noDefaultRepo` → `nil`; (4) else `["--repo", "default"]` (unchanged fallback).

3. **P3 — loopback-only by default.** The `--listen` flag default changes from `:18765` (all interfaces) to `127.0.0.1:18765` (loopback only); `--listen 0.0.0.0:18765` is the explicit opt-in for remote/container access. Help text states the loopback default. New `command_test.go` asserts the default is `127.0.0.1:18765`.

4. **New unit tests** (`candy/plugin-mcp/serve_test.go`): all four `computeProjectPrefix` branches (env dir set → nil, env repo set → nil, cwd charly.yml → nil, noDefaultRepo → nil, fallback → `--repo default`) plus `TestChildCharlyEnv_InheritsProjectEnv` proving `CHARLY_PROJECT_DIR` / `CHARLY_PROJECT_REPO` pass through the child env verbatim (no stripping).
