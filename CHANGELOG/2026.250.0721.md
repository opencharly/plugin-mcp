# 2026.250.0721 — feat(mcp-verb): substrate-neutral mcp_provide resolution from the check env (P4)

## Summary

P4 substrate-neutral resolution for the `mcp:` check verb (opencharly plan §3.10, spec #CheckEnv). Today `resolveMcpEndpoint` reads a deployment's mcp_provide declarations ONLY from the container `ai.opencharly.mcp_provide` OCI label via `cc.ResolveImageLabel` — a VM/host venue has no podman-inspectable image label, so the verb could not resolve there. The spec P4 tag (v0.2026250.709) threads the deployment's mcp_provide declarations into `#CheckEnv` (`MCPProvide []CandyMCPProvide`); this change consumes them:

1. **provider.go** — `mcpEnv` gains `McpProvide []spec.CandyMCPProvide` (the `mcp_provide` CheckEnv JSON decode), passed through invokeVerb's existing `env` argument.
2. **resolve.go** — the new pure `effectiveMCPProvides` source selector: the OCI label path stays authoritative when the label carries entries; when the label is absent/empty OR the label leg cannot inspect the venue (plugin-check refuses non-container venues with "container for %s is not running" — exactly the VM/host case), the env declarations are used, building the same entries slice (name/url/transport + Source from env.Box) and applying `PodAwareMCPProvides`. Dial methods rewrite the picked URL via `cc.ResolveEndpoint` (the vnc verb's pod+VM pattern) EXCEPT env-declared 127.0.0.1 URLs, which are already host-reachable and used as-is. The container label path is unchanged.
3. **go.mod** — spec pinned `v0.2026232.520` → `v0.2026250.709` (the P4 tag). sdk bumped `v0.2026234.347` → `v0.2026250.650`: the old sdk referenced `spec.FleetNode`, renamed to `DeployNode` in spec ≥ v0.2026250.656, so it cannot compile against the new spec.

Tests: 6 new resolveMcpEndpoint tests driven by a stub `kit.CheckContext` (env fallback resolves the env entry; the label path wins when present; a 127.0.0.1 env URL is used as-is with no rewrite; the label-leg ERROR falls back to the env — the real VM mechanism; a label-leg error with no env declarations propagates; no declarations → the hard "declares no mcp_provides" fail).
